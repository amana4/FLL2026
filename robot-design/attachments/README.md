# Attachments

Swappable mechanisms that mount to the chassis for a specific run.

One file per attachment. Copy [`_TEMPLATE.md`](_TEMPLATE.md) and name it after
the attachment (e.g. `gripper.md`, `lever-arm.md`).

## Design goals

1. **Fast to swap.** Under 10 seconds, one motion, ideally one hand. Seconds
   spent in Base are points not scored.
2. **Durable.** If it falls off mid-match it scores zero, however clever it is.
3. **Consistent mounting.** One mounting system means any attachment fits any
   time — see [`../chassis.md`](../chassis.md).
4. **Explainable.** Judges will ask why it's built this way. Record the
   alternatives you rejected.

## Version history

Keep old versions documented even after replacing them. The v1 → v3 progression
is direct evidence for the **Iterate** criterion in Robot Design judging — and
it's the thing teams most often fail to capture. Photograph each version before
you take it apart.
