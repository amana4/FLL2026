How gyro correction works

A real robot never drives straight on its own. The gyro is how it notices, and the correction is how it argues back. Four pictures.

1. The gyro measures how far off straight you are

One motor is stronger than the other, one tyre grips better, the battery sags. Over 20 cm you cannot see it. Over 90 cm it misses the model.

Zero the gyro before you move. From then on its reading is the angle between where you point now and where you started. Because you always want that to be zero, the reading is the error. Nothing to subtract.

await _settle()                  # let the gyro stop wobbling, 0.3 s
_reset_yaw(0)                    # now straight ahead means zero

error = _wrap180(_yaw_cw())      # this IS how far off you are

2. The correction speeds up one wheel and slows the other

Nothing steers a competition robot. It has two driven wheels and it turns by driving them at different speeds. So the correction is one number, and it goes onto one wheel as a plus and the other as a minus.

3. It does this 66 times a second

One correction is not the point. The loop is the point. Each pass is small and slightly wrong, and the next pass fixes what the last one missed.

4. Get the sign wrong and it runs away

The minus in front of the trim is the whole thing. It makes the correction push against the error. Turn it round and the correction pushes with the error: the error grows, so the push grows, so the error grows. The robot spins instead of driving. Engineers call the version that works negative feedback.

This happened to us. On 20 September 2026 a drive_cm(-44) spun on the spot instead of driving. The gyro on this hub counts up anticlockwise, not clockwise, so the correction was pushing the wrong way. The fix was one line — YAW_SIGN = -1 in advanced.py. Run bench_check_yaw_sign() after any rebuild and it tells you which value to use.
